# Отправка багов из ShellShifter

Код окна и приёмника готов. В текущей сборке адрес сервиса пустой: окно можно
открыть, написать описание и прикрепить картинку, но **Send отключена**. Для
реальной отправки владелец должен подключить свой Cloudflare и GitHub по этой
инструкции. Это однократная настройка; пользователям аккаунты не нужны.

## Что видит пользователь

**Updates → Report a Bug**: заголовок, описание, **Attach Screenshot**,
**Paste Screenshot** / Ctrl+V, предпросмотр, Remove и Send. После отправки
появляется **Open Report** со ссылкой на GitHub Issue.

Перед Send нужно поставить галочку согласия на публикацию. Репозиторий
`skazochnik3d/ShellShifter` публичный: текст и картинки смогут видеть все.
GitHub автором отчёта показывает аккаунт серверного токена. Отправитель не
авторизуется в GitHub; окно не сообщает его имя или email.

Автоматически добавляются только версии ShellShifter, Maya/API, Windows,
Python и Qt. Плагин не читает сцену или логи, не снимает экран автоматически
и не отправляет пути файлов. Пользователь выбирает или вставляет картинку
сам: видимое содержимое скриншота тоже публикуется.

## 1. Подготовить аккаунты

1. Зарегистрироваться на [Cloudflare](https://dash.cloudflare.com/sign-up).
   Включить двухфакторную аутентификацию на Cloudflare и GitHub.
2. Включить **R2 Object Storage**. Cloudflare может потребовать подключить
   биллинг; посмотреть текущие условия перед подтверждением. У R2 есть
   бесплатные квоты, но это не гарантия нулевой стоимости при любом трафике.
   [Тарифы R2](https://developers.cloudflare.com/r2/pricing/).
3. Установить [Node.js](https://nodejs.org/en/download) версии 22 или новее с npm. Для этой
   серверной папки используется закреплённый официальный Wrangler 4.151.0.
   Maya не требует установки Node или внешних Python-библиотек.

В PowerShell, находясь в корне исходного репозитория ShellShifter:

```powershell
Set-Location services/bug-reports
npm ci
npx wrangler login
npx wrangler r2 bucket create shellshifter-bug-screenshots
```

`wrangler login` открывает браузер для входа в Cloudflare. Не нужно передавать
пароли или токены в чат. Если вместо checkout скачан исходный ZIP без lockfile,
можно использовать `npm install` вместо `npm ci`.

## 2. Настроить приватное хранилище

В Cloudflare **R2 → shellshifter-bug-screenshots → Settings**:

- оставить **Public Development URL (r2.dev)** выключенным;
- не подключать публичный custom domain;
- создать **Object Lifecycle Rule** для префикса `screenshots/`: удалять объекты
  через **180 дней**. После удаления старый скриншот перестанет открываться в
  Issue, но описание останется. Это ограничивает накопление вложений.

Плагин не получает R2-ключи. Worker обращается к бакету через binding `IMAGES`.
Для чтения конкретной картинки нужна подписанная ссылка; список бакета
сервис не предоставляет. Ссылки опубликованных отчётов публичны, поэтому это
не механизм приватной поддержки.

## 3. Создать минимальный GitHub-токен

На GitHub открыть **Settings → Developer settings → Personal access tokens →
Fine-grained tokens → Generate new token**:

1. Название: `ShellShifter bug reports`.
2. Resource owner: `skazochnik3d`.
3. Repository access: **Only select repositories → ShellShifter**.
4. Repository permissions: **Issues → Read and write**. Metadata Read-only
   добавляется GitHub автоматически. Остальные права не включать: Contents,
   Administration, Actions, Workflows и права аккаунта сервису не нужны.
5. Указать срок действия, например 90 дней, и запланировать замену до истечения.

Этот токен может создавать и изменять Issues выбранного репозитория, а не
только добавлять новый отчёт. Поэтому он остаётся секретом даже с ограниченными
правами. Он не даёт записи кода или управления релизами при указанных настройках.
[Официальная инструкция GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

## 4. Разместить сервис выключенным

Файл `services/bug-reports/wrangler.jsonc` уже содержит R2, SQLite Durable Object
для общих квот и два ограничителя запросов. В первый раз оставить:

```json
"PUBLIC_ORIGIN": "",
"REPORTS_ENABLED": "false"
```

В серверной папке выполнить:

```powershell
npm test
npm run check
npm run deploy
npx wrangler secret put GITHUB_TOKEN
```

Токен вставляется только в скрытый запрос Wrangler. Не указывать его аргументом
команды, в конфигурации, исходниках, сообщении или скриншоте. Вместо CLI можно
добавить его в **Worker → Settings → Variables and Secrets**, выбрав тип **Secret**.
[Секреты Workers](https://developers.cloudflare.com/workers/configuration/secrets/).

Нужен ещё секрет `LINK_SECRET`: 32 случайных байта в виде 64 hex-символов.
Следующая команда создаёт его и передаёт напрямую в скрытый ввод Wrangler,
не выводя значение в терминал:

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))" | npx wrangler secret put LINK_SECRET
```

Включать отчёты до настройки обоих секретов не нужно. Секреты находятся в
Cloudflare; в дистрибутиве плагина их нет. `.env*`, `.dev.vars*` и файлы секретов
исключены из Git. Существующий токен `gh` на компьютере не используется сервисом.

## 5. Включить и связать с плагином

Wrangler покажет публичный адрес, например
`https://shellshifter-reports.YOUR-SUBDOMAIN.workers.dev` — это пример, не
уже работающий адрес. В `wrangler.jsonc` записать свой адрес без завершающего
слеша в `PUBLIC_ORIGIN`, а `REPORTS_ENABLED` поменять на строку `"true"`.

```powershell
npm run deploy
```

Открыть `<свой адрес>/health`: должно быть `{"schema":1,"enabled":true}`.
Это проверяет наличие конфигурации, но не подтверждает права/срок GitHub-токена.
Затем из корня репозитория выполнить, подставив собственный адрес:

```powershell
python tools/configure_reports.py https://shellshifter-reports.YOUR-SUBDOMAIN.workers.dev
python tools/build_release.py
```

Если отдельного Python нет, эти два скрипта можно запускать через `mayapy.exe`
из установленной Maya. `configure_reports.py` проверит health и запишет только
публичный адрес в `ShellShifter/uv_straight_report_config.py`. Обновить плагин
из новой сборки и перезапустить Maya.

Для распространения через автообновление увеличить `VERSION` в
`ShellShifter/uv_straight.py` до следующего номера (после локальной подготовленной
1.4.237 — 1.4.238), собрать архивы и опубликовать релиз после проверки доставки.
Установка файлов с тем же номером не обнаруживается как новое автообновление.

Провести один реальный тест: написать **TEST — setup check**, приложить
нейтральную картинку, отправить и открыть Issue. Проверить, что картинка
видна, а токен/пути файлов не попали в текст. Закрыть тестовый Issue. Это
окончательная проверка доставки; локальные тесты используют подмену GitHub.
Только после неё публиковать релиз с активной отправкой.

В [репозитории](https://github.com/skazochnik3d/ShellShifter) включить
**Watch → Custom → Issues**, в [настройках уведомлений](https://github.com/settings/notifications)
включить Email для Watching. Описание и скриншот будут в Issues; уведомления
о новых отчётах придут на подтверждённую почту GitHub. Поскольку токен создаёт
Issues от твоего аккаунта, включить также **Include your own updates**:
иначе GitHub может не присылать письма о действиях, выполненных от твоего имени.

## Защита и ограничения

- HTTPS с проверкой сертификата; плагин не следует перенаправлениям при отправке.
- Картинки PNG/JPEG до 8 MB и 16 мегапикселей на входе плагина. Перед отправкой
  они уменьшаются до 1600 px по длинной стороне и переупаковываются в PNG
  до 2 MB без исходных метаданных/имени файла.
- Сервер самостоятельно проверяет PNG, размеры, CRC, структуру и ограниченное
  распакованное содержимое; удаляет метаданные. SVG, HTML, архивы и исполняемые
  файлы не принимаются. Картинки выдаются как image/png с nosniff/CSP.
- Текст отчёта отображается буквально, без исполнения HTML и массовых @mentions.
- До 5 запросов отправки в минуту на IP; до 3 новых отчётов в сутки на IP
  и **20 попыток отправки в сутки на весь сервис**. Повторы после явного отказа
  GitHub тоже расходуют суточную квоту. Суточные лимиты атомарны в
  Durable Object; смена IP или перезапуск Worker общий лимит не сбрасывает.
  Сутки считаются по UTC. На общей офисной сети лимит делят все пользователи.
- Повтор одного запроса сохраняет результат 7 дней. После неопределённого
  ответа GitHub сервис не повторяет создание автоматически. Пользователь
  видит предложение проверить Issues перед созданием нового отчёта.
- Сырые IP не записываются нашим кодом: для квот используется HMAC. Cloudflare
  обрабатывает IP для работы сети и своей защиты. Логи запросов в проекте
  отключены; при включении отладки не логировать тела/Authorization/ссылки.
- Нет фоновых проверок для репортинга: сеть включается только после Send;
  отправка идёт в отдельном потоке, сцену и Undo плагин не меняет.

Это снижает риски, но не гарантирует абсолютной защиты. Анонимный сервис
всё ещё может получить спам или отказ в обслуживании. Лимиты вложений/Issues
не являются общим ограничением счёта Cloudflare: настроить уведомления о
расходах и проверять использование. Не включать автоматическое повышение
тарифа без необходимости. У 2FA и минимального токена разные задачи:
2FA защищает вход в аккаунт, права токена ограничивают ущерб при его утечке.

При атаке поставить `REPORTS_ENABLED: "false"` и выполнить deploy. При
подозрении на утечку отозвать токен GitHub и заменить Secret. При замене
`LINK_SECRET` старые подписанные ссылки на картинки перестанут работать.
Если скриншот нужно убрать, удалить соответствующий объект из R2 и убрать
ссылку из Issue; уже скопированное кем-либо содержимое отозвать нельзя.
